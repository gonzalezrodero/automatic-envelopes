## Learnings

### 2026-11-21 — Onboarding

#### Architecture

- One .NET 10 host, `src/AutomaticEnvelopes.Api`. `Program.cs` loads secure configuration, Marten, features, Wolverine, and Wolverine HTTP, then Lambda HTTP hosting. `SqsLambdaHandler.cs` is the SQS entry and calls the same `AddDatabase` / `AddFeatures` / `AddWolverine` path.
- A vertical slice is a folder under `src/AutomaticEnvelopes.Api/Features/`. HTTP methods use `[WolverineGet]`, `[WolverinePost]`, `[WolverinePatch]`, or `[WolverineDelete]` and `Program.cs` maps them with `MapWolverineEndpoints`. A command or event is a record. A handler is a static `Handle` method. Wolverine discovers the API assembly from `Config.AddWolverine` (`Discovery.IncludeAssembly`). A saga is a `Saga` with `[Identity]` in that feature folder (`Features/Chat/ChatDebounceSaga.cs`). `Config.AddFeatures` is the registration list (WhatsApp options, chat, webhook, knowledge, dispatcher).
- Marten tenancy is set once in `Config.AddDatabase`. Events use `StreamIdentity.AsString` and `TenancyStyle.Conjoined`. `TenantProfile` is `SingleTenanted`. `ProcessedMessage`, `DocumentChunk`, `WhatsAppRateLimitTracker`, `TenantMonthUsage`, `KnowledgeFile`, `AnonymizedChat`, and `UnansweredQuestion` are `MultiTenanted`. Tenant-owned work uses `IDocumentStore.LightweightSession(tenantId)`. The tenant catalog uses `QuerySession()` because `TenantProfile` is single-tenanted (`Features/WhatsAppWebhook/ProcessWhatsAppMessageHandler.cs`). Portal and admin routes authorize with `TenantAccess` (`PlatformAdmin` versus `TenantAdmin`; a Cognito group name is the tenant id). `TenantIds` allows `^[a-z0-9-]+$`, length at most 64, and reserves the group `admin`.
- Deployed Lambdas do not own the schema. `DatabaseSchemaStartup` turns on Marten auto-create only when `AWS_LAMBDA_FUNCTION_NAME` is empty. With a function name set, `Config.AddDatabase` forces `AutoCreate.None` and `ResourceAutoCreate.None`. Schema changes are SQL in `db/migrations/`, applied as the RDS master by `.github/scripts/db-migrate.sh` through `reusable-db-migrate.yml`. Recorded versions live in `ops.schema_migrations`, which the script leaves ungranted to `marten_app`.
- Published messages are explicit in `Config.AddWolverine`: `ProcessWhatsAppMessage` to `automatic-envelopes-messages-queue`, `ChatWindowExpired` to `automatic-envelopes-system-queue`, raw JSON, inline send. Listeners start only when `EnableSqsListener` is true. Phone numbers in logs go through `LogMask.Phone`.
- Infra is one stack per directory under `infra/`. Apply, plan, and approval stay on the workflow that already points at that directory. Review reads the diff.

#### Conventions

- Public repo (`.squad/decisions.md`). Configuration is named, never valued, in committed files: `SECRET_ARN_MARTEN`, `SECRET_ARN_USAGE`, `SSM_PATH_WHATSAPP`, `DB_HOST`, `ConnectionStrings:Marten`, `Usage:PhoneHashKey`, `WhatsApp:AppSecret`, `WhatsApp:VerifyToken`, `WhatsApp:AccessToken` (`AwsConfigurationExtensions.cs`). Values belong in Secrets Manager, SSM, or the gitignored files `appsettings.Development.json` and `secrets.json`.
- Minimal diff (`.squad/decisions.md`). Stay inside the existing slice, the single API project, the single test project, and the current Marten and Wolverine patterns. Routing: Backend owns `src/AutomaticEnvelopes.Api` and `db/migrations/`; Tester owns `tests/AutomaticEnvelopes.Tests`; Infra owns `infra/**` as a diff only; Reviewer reviews and is never the author.
- GitHub text is English: issues, pull requests, commit messages, code comments, and docs. Product copy a feature already sends to users stays in that feature's language.
- Migration filename: `db/migrations/YYYYMMDD_NNN_snake_name.sql`. `db-migrate.sh` `valid_version` accepts only `^[0-9]{8}_[0-9]{3}_[a-z0-9_]+\.sql$`. Optional header lines, exact prefix match: `-- migrate: apply-if-missing schema.object`, `-- migrate: apply-if-present schema.object`, `-- migrate: skip-if-applied <filename.sql>`, `-- migrate: transfers-ownership-from marten_app`. Object names match `valid_ident` (`schema.object`, lowercase). Patches are generated with `dotnet run --project src/AutomaticEnvelopes.Api -- db-patch <file>`, as `20261028_001_chat_debounce_window_claim.sql` records. A new table grants `SELECT, INSERT, UPDATE, DELETE` on that table to `marten_app`.
- Tests are xUnit and AwesomeAssertions in `tests/AutomaticEnvelopes.Tests`. Pure rules are plain `[Fact]` classes (`Features/Usage/UsageRulesTests.cs`). Anything that boots the app uses `[Collection("Integration")]` and `IntegrationAppFixture`. HTTP uses `fixture.Host.Scenario`. A handler uses `InvokeMessageAndWaitAsync`. Tenants are seeded with `SeedTenantAsync` and a synthetic id.
- Terraform CI only. `pr-terraform.yml` plans dev and has no apply job. Its matrix is `bootstrap`, `network`, `db`, `serverless` (also `infra/modules`), and `portal`. Apply workflows: `bootstrap.yml` and `network.yml` call `reusable-terraform.yml`; `db.yml` calls that plus `reusable-db-migrate.yml`; `deploy.yml` runs `build-and-test`, then migrations, then `reusable-serverless.yml` (`infra/serverless`), then `reusable-api-domain.yml` (`infra/api-dns`, then `infra/api-delegation`); `portal.yml` calls `reusable-portal.yml` (`infra/portal`). `destroy.yml` is `workflow_dispatch` inside CI.
- A verdict is APPROVE or REJECT, recorded with `squad_decide`, and tied to the request or to `.squad/decisions.md`. A required change is a REJECT. Reviewer does not patch the files under review, does not edit `.github/workflows/`, and does not run Terraform or the AWS CLI.
- Copilot projection stays uncommitted (`.squad/decisions.md`): `.github/agents/`, `.github/skills/`, `.mcp.json`, `.copilot/`, `.squad/templates/`. Cursor loads `.cursor/`. Team state stays in `.squad/`.

#### Gotchas

- REJECT a committed secret, WhatsApp or Meta value, customer record, or tenant record. Grounded in `.squad/decisions.md` and `AwsConfigurationExtensions.cs`: the committed surface is the names `SECRET_ARN_MARTEN`, `SECRET_ARN_USAGE`, `SSM_PATH_WHATSAPP`, `ConnectionStrings:Marten`, `Usage:PhoneHashKey`, and `WhatsApp:*`. `.gitignore` keeps `appsettings.Development.json`, `secrets.json`, `*.tfstate`, and `.terraform/` out of git. `infra/db/marten_app.tf` stores the role password as `ephemeral.random_password` and `secret_string_wo`. A plaintext password, a real token, a connection string with a password, a raw phone number in a log line (`LogMask.Phone` in `ProcessWhatsAppMessageHandler.cs` and `ChatDebounceSaga.cs`), or a customer prompt is a REJECT. The integration fixture's placeholders stay inside `IntegrationAppFixture.cs`.
- REJECT a diff that runs or instructs `terraform apply`, `terraform destroy`, or a mutating AWS CLI command, and a workflow edit that moves apply off the existing pipeline. Grounded in `.squad/decisions.md`. Apply jobs already live in `reusable-terraform.yml`, `reusable-serverless.yml`, `reusable-portal.yml`, `reusable-db-migrate.yml`, `reusable-api-domain.yml`, and `destroy.yml`. `pr-terraform.yml` stops at plan (dev, `-lock=false`; the db stack adds `-refresh=false`). `infra/api-dns` and `infra/api-delegation` are applied from `deploy.yml` via `reusable-api-domain.yml` and are absent from the `pr-terraform.yml` path filters, so a review of those folders expects no PR plan comment from that workflow.
- REJECT a rename of CI job `build-test`, `build-and-test`, or `sonarcloud`, a rename of the SonarCloud step `Build`, or any other edit to a workflow job id or job `name:`. Grounded in `.squad/decisions.md` and the job ids in `pr-check.yml`, `deploy.yml`, and `sonarcloud.yml`. Reviewer does not edit `.github/workflows/`.
- REJECT a diff broader than the request. Grounded in `.squad/decisions.md` (minimal code and tests; Copilot projection stays uncommitted). Extra projects, new frameworks, drive-by refactors, restored `.github/agents/`, `.github/skills/`, `.mcp.json`, `.copilot/`, or `.squad/templates/`, and committed `Internal/Generated/` (gitignored) are REJECTs. New GitHub-facing text that is not English is a REJECT; existing Spanish in `db-migrate.sh` and `20261026_002` stays as history unless the diff itself adds more.
- REJECT a migration whose filename fails `valid_version` in `db-migrate.sh`, a `-- migrate:` line that misses the exact prefix, an object name that fails `valid_ident`, or an edit to an already applied file (the script exits on checksum mismatch). REJECT a new Marten table that omits `GRANT SELECT, INSERT, UPDATE, DELETE ... TO marten_app` on that table (`20261028_001_chat_debounce_window_claim.sql`). REJECT a schema change that depends on the fixture: `IntegrationAppFixture` sets `AutoCreate.All`, while `DatabaseSchemaStartup` and `Config.AddDatabase` keep deployed Lambdas on `AutoCreate.None`.
- REJECT a new tenant-scoped document registered in only one of `Config.AddDatabase` and the `Configure<StoreOptions>` list in `IntegrationAppFixture.cs`. REJECT tenant data opened outside `LightweightSession(tenantId)`, and a change that makes `TenantProfile` multi-tenanted or skips `TenantIds` / `TenantAccess`. REJECT a new published message that is missing from `Config.AddWolverine`, from the queue setup in `IntegrationAppFixture`, or from `infra/serverless` when the request includes that queue.
- REJECT a test that calls live Meta, Bedrock, SES, or AWS. The fixture replaces `IAmazonBedrockRuntime`, `IWhatsAppClient`, and `IAmazonSimpleEmailServiceV2` and starts local pgvector and ElasticMQ containers. REJECT an app-booting test that is outside collection `Integration`. Behavior changes still need an xUnit test here; `pr-check.yml` `build-test` will not run it.
