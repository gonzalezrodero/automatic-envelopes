### 2026-11-21 — Onboarding

#### Architecture

One web project, `src/AutomaticEnvelopes.Api` (`net10.0`). `Program.cs` composes the HTTP Lambda. `SqsLambdaHandler` is a second host for SQS. There is no other backend project.

`Program.cs` order: JSON console logs, `AddAwsSecureConfiguration`, `ConnectionStrings:Marten`, `AddAdminPortalAuth` plus policies, rate limiting, `AddDatabase`, `AddAi`, `AddFeatures`, `AddWolverine`, OpenAPI, Wolverine HTTP, `AddAWSLambdaHosting(LambdaEventSource.HttpApi)`. Unless the arg is `codegen`, startup may apply Marten changes and then always calls `EnsureVectorExtensionExists`. Pipeline: CORS `AdminPortal`, authentication, `AdminCsrfMiddleware`, authorization, rate limiter, `MapWolverineEndpoints`, `RunJasperFxCommands`.

`DatabaseSchemaStartup.AppliesAtStartup` is true only when `AWS_LAMBDA_FUNCTION_NAME` is empty. That is the deployed signal. `ASPNETCORE_ENVIRONMENT` is not: the dev Lambda is `Development` and still must not own the schema. When the name is set, `Config.AddDatabase` sets JasperFx `ResourceAutoCreate` and Marten `AutoCreateSchemaObjects` to `AutoCreate.None` for Development and Production. Local `dotnet run` and the Alba host leave auto-create on. Tests in `IntegrationAppFixture` force `AutoCreate.All`; that override stays in the test host.

Marten (`Config.AddDatabase`): Npgsql data source, `StreamIdentity.AsString`, `TenancyStyle.Conjoined`, `UseLightweightSessions`, Wolverine outbox with `UseWolverineManagedEventSubscriptionDistribution`. `HnswIndexCustomizer` is an `IFeatureSchema`. `ProcessedMessageProjection` is inline. `TenantProfile` is `SingleTenanted`. These are `MultiTenanted`: `ProcessedMessage`, `DocumentChunk`, `WhatsAppRateLimitTracker`, `TenantMonthUsage`, `KnowledgeFile`, `AnonymizedChat`, `UnansweredQuestion`. Conjoined tables use `tenant_id` in the primary key. The initial SQL then `DISABLE ROW LEVEL SECURITY` and drops `marten_tenant_isolation`. Isolation is the session and the SQL predicate, not RLS.

`AddAi` is the only Bedrock and SES wiring: `BedrockSettings`, `UsageOptions`, `AddDefaultAWSOptions`, one `IAmazonBedrockRuntime`, one `IAmazonSimpleEmailServiceV2`, singleton `UsageMeter`, scoped `IChatService`/`ChatService`, scoped `IEmbeddingService`/`EmbeddingService`. `AddChatFeature` registers `IChatService` again as the same type. Chat calls `ConverseAsync` with `BedrockSettings.ModelId`. Embeddings call `InvokeModelAsync` on that same client with model id `amazon.titan-embed-text-v2:0`, `dimensions` 512, `normalize` true. `extract_embedding` casts JSON `Embedding` to `vector(512)`. `Microsoft.Extensions.AI` supplies `ChatMessage` / `ChatRole` only. There is no second chat client.

Wolverine (`Config.AddWolverine`): discovers `typeof(Program).Assembly`, `AlwaysUseServiceLocationFor<IWhatsAppClient>` because the Refit client is generated, `AutoApplyTransactions`, `ThrottlingException` cooldown 3s then 30s, `ConcurrencyException` cooldown 50/100/250 ms (rate-limit tracker collisions), `DurabilityMode.Solo`. `AWS_ENDPOINT_URL_SQS` sets the SQS service URL and `AuthenticationRegion` `us-west-1`. `SystemQueuesAreEnabled(false)`. Publish `ProcessWhatsAppMessage` to `automatic-envelopes-messages-queue` and `ChatWindowExpired` to `automatic-envelopes-system-queue`, both `SendInline` with `RawJsonSqsMapper`. Listen on those queues only when `EnableSqsListener` is true. The HTTP Lambda publishes and returns. The worker is `SqsLambdaHandler.FunctionHandler`: system-queue ARN goes to `ChatWindowExpired`, otherwise `ProcessWhatsAppMessage`, partial batch failures, cancel 500 ms before the Lambda deadline. The worker builds its own host (`AddDatabase`, `AddAi`, `AddFeatures`, `AddWolverine`) and does not call `EnsureVectorExtensionExists`.

`Dockerfile`: `mcr.microsoft.com/dotnet/sdk:10.0`, restore the csproj, copy sources, delete `bin`/`obj`, `dotnet run --project AutomaticEnvelopes.Api.csproj -- codegen write`, `dotnet publish` Release `/p:UseAppHost=false`, then `public.ecr.aws/lambda/dotnet:10` with the publish output at `/var/task`. No `CMD` in the file. Production codegen mode is `TypeLoadMode.Static`; Development is `Auto`. `codegen` skips secret fetch and the schema block.

WhatsApp intake lives in `Features/WhatsAppWebhook`. `WhatsAppWebhookEndpoint` is `GET` and `POST` `/api/whatsapp/webhook`. GET compares `hub.verify_token` to `WhatsApp:VerifyToken` with `FixedTimeEquals` and returns the challenge as text. POST rejects a bad `X-Hub-Signature-256` HMAC (`WhatsAppPayloadProcessor`, key `WhatsApp:AppSecret`) with 401, parses one user text into `ProcessWhatsAppMessage`, and `PublishAsync`s it. `ProcessWhatsAppMessageHandler` loads `TenantProfile` by `BotPhoneNumberId` on a non-tenant `QuerySession` (the document is single-tenanted). It then opens `LightweightSession(tenant.Id)`, drops the message if `ProcessedMessage.Id` already exists, and rate-limits at 25 messages per minute. The tracker id is `PhoneRateKey.TryHash` (HMAC-SHA256 of tenant id + phone, secret `Usage:PhoneHashKey`, minimum 16 chars), never the phone. A raw delete removes tracker rows for that `tenant_id` whose id is not 64 hex chars. Over the limit, it saves the tracker and returns without an event. Otherwise it appends `MessageReceived` to the stream whose id is the phone number and `InvokeAsync`s that event. `ProcessedMessageProjection` stores `ProcessedMessage` inline. Saga id is `ChatSagaIds.For`: `{tenantId}:{phoneNumber}`.

Chat lives in `Features/Chat`. `ChatDebounceSaga.StartsOrHandles` concatenates text up to 4000 characters, opens the window once, deletes any prior `ChatDebounceMarker` for that saga id, and emits `ChatWindowExpired` carrying `StartedAt` ticks. The log line calls this the SQS native delay. The queue delay is not set in the API. The test host creates `automatic-envelopes-system-queue` with `DelaySeconds` 10. `StuckAfter` is 10 minutes. `ChatDebounceRecovery.RepublishDueAsync` republishes overdue windows under a lease row `ChatDebounceMarker.RecoveryId` (`"recovery"`). `ChatWindowExpiredHandler` locks `mt_doc_chatdebouncesaga` with `FOR UPDATE`, ignores a tick mismatch, skips a marker whose `ClaimedVersion` equals `saga.Version`, invokes `AnalyzeChatSession` in the same attempt, deletes the saga only if `mt_version` still matches, and inserts the claim marker. `ChatSessionHandler` opens `LightweightSession(command.TenantId)`, loads `TenantProfile` by that id, and on `BotPrompts.DeleteCommands` publishes `DeleteChatHistoryCommand`. Otherwise it reads the tenant stream, and if `UsageMeter.ResponseCountAsync` is at `EffectiveMonthlyResponseLimit` (document value, or `DefaultMonthlyResponseLimit` 1000) it sends the limit reply. Under the limit it searches knowledge, builds the system prompt in `BotPrompts`, calls `IChatService.GetResponseAsync` with `tenant.EnabledTools`, prepends the first-contact notice when no assistant turn exists, appends `ReplyGenerated`, and `UsageMeter.RecordAsync` counts tokens only after the reply is stored. `ThrottlingException`, `ConcurrencyException`, and cancellation propagate. Other failures before the reply is stored get one fallback reply. `DeleteChatHistoryHandler` deletes `mt_events` and `mt_streams` with both `stream_id` and `tenant_id`. `TenantToolGate.KnownNames` is an empty list, so `Select` attaches no tools unless that list and the tenant's `EnabledTools` both contain the name. `IBedrockTool` plus `ToolExecutionService` run one tool-use round trip on the same `ConverseRequest`. Unknown answers and the portal inbox are `UnansweredQuestion`, `UnansweredInbox`, `RecordUnansweredQuestionHandler`, `ForgetUnansweredConversationHandler`. Answered text is re-indexed as knowledge file `AnsweredKnowledge.FileName` (`respuestas.md`), which `IngestLimits.RejectReservedName` refuses as an upload.

Dispatch lives in `Features/WhatsAppDispatcher`. `ReplyGeneratedHandler` loads a token from `IWhatsAppAccessTokenSource` and calls Refit `IWhatsAppClient.SendMessageAsync` with the event's `BotPhoneNumberId`. When `SSM_PATH_WHATSAPP` is set, `WhatsAppAccessTokenSource` reads `/automatic-envelopes/whatsapp/tenants/{tenantId}/access-token` (5-minute cache). Without that env var it uses `WhatsApp:AccessToken`. `AddAwsSecureConfiguration` does not copy an SSM parameter named `access-token` or any path containing `/tenants/` into `WhatsApp:*`.

Knowledge lives in `Features/Knowledge`. `IngestEndpoint` is `POST /api/admin/ingest/{tenantId}` (`TenantAdmin`, `AdminPolicy`, `RequestSizeLimit` = `IngestLimits.MaxUploadBytes` = 4 MiB). The attribute binds only on Kestrel. Lambda rejects on `file.Length`. Caps: 100 PDF pages, 200000 characters, 64 MiB decoded Flate output via `BoundedFlateFilterProvider`. Extractors: `TextDocumentExtractor`, `PdfDocumentExtractor`. `KnowledgeIngestionService` chunks 1000 characters with 200 overlap, replaces chunks for the same filename, and does not clear the rest of the tenant. `KnowledgeCatalog` / `KnowledgeFile` record the file. `KnowledgeBaseService.SearchAsync` embeds the query and runs `extract_embedding(data) <=> CAST(? AS vector)` with `WHERE tenant_id = ?` on `LightweightSession(tenantId)`. Portal upload is a second route, `POST /tenants/{tenantId}/documents`, using the same limits and services.

Tenancy lives in `Features/Tenancy`. `TenantIds` is `^[a-z0-9-]+$`, max 64, and `admin` is reserved. `TenantAccess`: group `admin` is platform admin; any other Cognito group is a tenant id; `CanAccess` allows admin or a matching group. Policies in `Config.AddCustomAuthorization`: `PlatformAdmin` and `TenantAdmin` (route `tenantId`). `RegisterTenantEndpoint` is `POST /api/admin/tenants/{tenantId}` (`PlatformAdmin`, `AdminPolicy`). `TenantEndpoints`: `GET /tenants`, `GET` and `PATCH /tenants/{tenantId}`, `GET /tenants/{tenantId}/usage`. PATCH body is `UpdateTenantSettingsRequest`. `enabledTools`, `monthlyResponseLimit`, and `contactEmail` are platform-admin fields. `TenantSettingsValidation` checks the prompt and the privacy URL. `TenantPortalProfile` is the JSON shape. Portal and tenant routes also call `TenantRequest.Reject` and set `Cache-Control: no-store`.

Portal lives in `Features/Portal`. `PortalEndpoints` (`TenantAdmin`, `AuthPolicy`): dashboard, conversations, one conversation, documents, unanswered list, answered list, answer, revision, delete, discard, document upload (`AdminPolicy`), document delete. Reads of events go through `PortalConversations.ReadAsync`, which opens `LightweightSession(tenantId)` and still filters `evt.TenantId == tenantId`. `PortalDashboardBuilder` summarizes. `PortalPhone` / `PortalIds` / `PortalClock` are the small helpers. The injected HTTP `IDocumentSession` is the default tenant. `TenantProfile` loads are valid there because it is single-tenanted. Multi-tenant documents are not.

Usage lives in `Features/Usage`. `TenantMonthUsage` is one document per tenant and `UsageMonth` key `yyyy-MM` in `Europe/Madrid`. `UsageMeter` upserts `public.mt_doc_tenantmonthusage` on `(tenant_id, id)` and emails at 80% and 100% through SES when `Usage:FromAddress` and `ContactEmail` are set. Failures are logged and swallowed. `UsageMessages` holds the limit copy.

Admin auth lives in `Features/AdminAuth`. `AuthEndpoints`: `POST /auth/token`, `GET /me`, `POST /auth/logout`. Cookies `ae_access` (path `/`) and `ae_id` (path `/me`), HttpOnly. JwtBearer reads `ae_access` only when `Authorization` is absent. Access tokens are checked with `CognitoAudienceValidator` against `client_id`. `GET /me` reads the ID token via `CognitoIdTokenReader`. `AdminCsrfMiddleware` requires an allowed `Origin` on unsafe cookie-authenticated portal calls and on `/auth`. `AdminAuthOptions.FromConfiguration` prefers env lists and rejects `*`. Empty origins prevent startup. `COGNITO_USER_POOL_ID` is required outside Development and Testing. Rate limits are in-memory per Lambda instance: `AdminPolicy` 10/min (register and both ingest routes), `AuthPolicy` 60/min (auth, `/me`, tenant and portal reads). Partition key is caller plus lowercased path without a trailing slash. Auth uses the client IP. Admin uses JWT `sub`, else IP.

#### Conventions

Match the feature folder that already owns the behavior. HTTP endpoints are Wolverine HTTP attributes on a static method or a small endpoint type in that folder, with `[Authorize]` and `[EnableRateLimiting]` on the action. Handlers are `public static Task Handle(...)` in the same feature. Marten documents and events stay next to that feature (`Core/Entities`, `Core/Events` for the shared stream types). Do not add a project, a framework, or a parallel client.

Multi-tenant reads and writes use `IDocumentStore.LightweightSession(tenantId)` and, for hand-written SQL, a `tenant_id` parameter. `TenantProfile` lookups by phone-number id stay on `QuerySession` because the document is single-tenanted. Saga rows are not conjoined: `ChatDebounceSaga` id is `tenantId:phone`, and `ChatWindowExpiredHandler` locks by that id on the default session.

Do not log phone numbers, access tokens, verify tokens, app secrets, hash keys, prompt or message text, tool arguments, or document contents. Phones go through `Common/LogMask.Phone` (SHA-256 hex, first 32 chars). Logs that exist today record tenant id, message id, bot phone-number id, counts, and model id.

Bedrock stays on the `IAmazonBedrockRuntime` from `AddAi`. Chat model id, max tokens, and temperature come from `BedrockSettings`. The embedding model id and 512 dimensions stay in `EmbeddingService`, matched to `vector(512)`.

Schema changes are reviewed SQL in `db/migrations`, not startup. Name `YYYYMMDD_NNN_descripcion_en_snake_case.sql`. Lexical order is apply order. `NNN` orders two files from the same day. The files on disk:

#### Gotchas

Deployed processes must not apply schema. `AppliesAtStartup` is false whenever `AWS_LAMBDA_FUNCTION_NAME` is set, and both critter environments then use `AutoCreate.None`. Turning auto-create back on, or calling `ApplyAllConfiguredChangesToDatabaseAsync` from the Lambda path, fights the versioned SQL and runs as `marten_app`, which cannot own those objects. The dev Lambda is still `Development`, so an environment check would do the wrong thing. `Program.cs` calls `VectorSchema.Ensure` even when the Marten apply is skipped. That method `CREATE EXTENSION vector` and `CREATE FUNCTION public.extract_embedding` if they are missing. `marten_app` cannot create the extension (`InsufficientPrivilege`). Do not add more DDL there. The HNSW index is `HnswIndexCustomizer.WriteTemplate` (`mt_doc_documentchunk_idx_embedding` on `extract_embedding(data) vector_cosine_ops`). It is not in any file under `db/migrations`. A new index ships only as a reviewed migration.

`db-patch` runs after that startup block. With `AWS_LAMBDA_FUNCTION_NAME` unset, the process applies the configured Marten schema before JasperFx writes the file, so the diff can miss objects startup just created. Generate against a database that already has the previous committed patches, then review. `mt_doc_chatdebouncesaga` is queried in `ChatWindowExpiredHandler` and described as unchanged by `20261028_001`, and it is not created in `20261026_001`. A patch that only adds a marker will not create the saga table on an empty database. `ChatDebounceMarker` is also absent from `Schema.For`. Follow the existing name pattern, including the Spanish snake_case used by the four files. Keep `001` as the empty-database script with `apply-if-missing`, keep `003` behind `skip-if-applied` of `001`, and keep ownership transfer in front of any later `ALTER` that the master must run. New tables need an explicit `GRANT` to `marten_app`. Do not grant `CREATE` more widely and do not make `marten_app` the owner.

Do not add a second Bedrock stack. Chat and embeddings already share `IAmazonBedrockRuntime` from `AddAi`. A new `IAmazonBedrockRuntime`, a `Microsoft.Extensions.AI` chat client, or a hard-coded chat model id next to `BedrockSettings` splits usage, retries, and the 512-dimension index. `TenantToolGate.KnownNames` is empty, so registering an `IBedrockTool` does nothing until that allowlist and the tenant `EnabledTools` both name it. Tool execution logs the argument JSON at Debug. Do not log that, the system prompt, the user text, or retrieved chunks.

Do not log phones, tokens, or customer text. `LogMask.Phone` is the existing mask. `PhoneRateKey` stores an HMAC, and a startup delete strips non-hash tracker ids. `SqsLambdaHandler` masks `ChatWindowExpired.SagaId` because the id contains the phone. Webhook logs record whether the verify token matched, not the token. SSM mapping skips tenant access tokens on purpose. `WhatsAppAccessTokenSource` logs the tenant id after a load, not the value.

Wrong slice: webhook verification and HMAC stay in `WhatsAppWebhook`. Graph send and the per-tenant token stay in `WhatsAppDispatcher`. Debounce, the model call, deletion, and the unanswered inbox stay in `Chat`. Ingest limits, extraction, chunking, and vector search stay in `Knowledge`. Portal routes call those services. They do not grow a second ingestor. Profile, group checks, and registration stay in `Tenancy`. Cookies, CSRF, and Cognito stay in `AdminAuth`. Quota math stays in `Usage`. `Features/Tenants/Helpers/JsonConverter.cs` is only the tool-argument serializer.

Wrong tenant scope: a handler that takes the HTTP `IDocumentSession` and queries `DocumentChunk`, events, or usage will see the default tenant. Open `LightweightSession(tenantId)` and keep `tenant_id` in raw SQL. `KnowledgeBaseService` and `UsageMeter` already do both. RLS is disabled on the conjoined tables, so a policy will not save a missing predicate. Saga state is isolated by `{tenantId}:{phone}` on a table with no `tenant_id` column. Do not mark that saga multi-tenanted without a migration and a session change. Deleting history must constrain `mt_events` and `mt_streams` by `tenant_id`, as `DeleteChatHistoryHandler` does.
